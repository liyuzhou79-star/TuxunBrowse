# 指纹模式对标表

本表把 TuxunBrowse 指纹模式与同赛道产品逐项对照，状态只写实测与代码可证的结论，
不写规划当现状。对标对象：

- **Octo Browser 安卓版**（商业，原生安卓 App，Chromium 内核级伪装）
- **GoLogin 安卓版**（商业，原生安卓 App，Orbita＝Chromium 分叉）
- **Camoufox**（开源，桌面 Firefox 的 C++ 级补丁）
- **Apify fingerprint-suite**（开源，桌面 JS 注入＋真实设备分布生成）
- **fingerprint-chromium**（开源，桌面 Chromium 补丁）

状态记号：**有**＝已实现且有测试/真机证据；**部分**＝有近似或覆盖不全；
**缺**＝没有，且在现有路线内可补；**结构性做不了**＝WebView 嵌入路线（不改内核、
不自带引擎）的边界，写清原因，不装有。

注 1（存储隔离）：androidx.webkit 多档案 API 已接入：指纹标签创建时绑定一个
独立 Profile（独立 CookieManager、WebStorage、ServiceWorker），Cookie 政策与
指纹标签的下载请求都改读对应存储，设置里的「清除数据」会把所有指纹存储一起清。
下载记录带出身：从下载页对指纹来源的失败记录点重试，仍按记录所属组合的存储
取 Cookie（v0.205.0），不会因为已切换组合或退出模式就串到普通登录。
隔离粒度：v0.196.0 是「指纹模式整体一份」（名为 tuxun_fp）；v0.198.0 起细化到
每个「地区＋机型」组合一份——不同组合打开同一网站互不相通登录态，切回原组合
登录还在。时区与语言不另分存储：它们是同一人设的呈现设置（真人换手机时区不会
丢登录），组合总数被机型库封顶（4 地区 × 4 机型）。旧版那一份 tuxun_fp 不会被
丢弃：升级后第一个被选中的组合继续用它（当时模式只呈现过这一个身份），其余
组合各起新存储。运行时按宿主 WebView 的能力探测：不支持多档案的 WebView 回落
到与普通模式共用一份存储，模式首页的说明按实际能力显示，不提前宣称隔离。

注 2（代理）：androidx.webkit 的 ProxyController 是全 App 级覆盖（对所有 WebView
生效、Gecko 不受影响），没有逐连接粒度。v0.197.0 落地「指纹模式级」绑定：进入
模式时应用、退出时清除。v0.198.0 起配置按「地区＋机型」组合分别保存：切换组合
时自动换用该组合保存的代理（没存过则直连），模式首页的代理卡写明当前组合的
代理、这期间普通 WebView 标签也会走同一代理、并提示用 IP 自查验出口；系统接口
不支持带账号密码的代理，表单只收主机与端口并写明。两个组合的流量无法在同一
时刻走不同代理（模式同一时间只呈现一个身份，打开的窗口内只有一个覆盖），这是
平台粒度决定的边界，不是配置缺失。

本表随版本更新；每项状态变化时同步改表并在检查点记明依据。
