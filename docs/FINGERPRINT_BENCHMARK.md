# 指纹模式对标表

本表把 TuxunBrowse 指纹模式与同赛道产品逐项对照，状态只写实测与代码可证的结论，
不写规划当现状。对标对象：

- **Octo Browser 安卓版**（商业，原生安卓 App，Chromium 内核级伪装）
- **GoLogin 安卓版**（商业，原生安卓 App，Orbita＝Chromium 分叉）
- **Camoufox**（开源，桌面 Firefox 的 C++ 级补丁）
- **Apify fingerprint-suite**（开源，桌面 JS 注入＋真实设备分布生成）
- **fingerprint-chromium**（开源，桌面 Chromium 补丁）

状态记号：**有**＝已实现且有测试/真机证据；**部分**＝有近似或覆盖不全；
**缺**＝没有，且在现有路线内可补；**结构性做不了**＝WebView 嵌入路线（不改内核、
不自带引擎）的边界，写清原因，不装有。

注 1（存储隔离）：v0.196.0 已接入 androidx.webkit 多档案 API：指纹标签创建时绑定
名为 tuxun_fp 的独立 Profile（独立 CookieManager、WebStorage、ServiceWorker），
Cookie 政策与指纹标签的下载请求都改读这个存储，设置里的「清除数据」会连它
一起清。运行时按宿主 WebView 的能力探测：不支持多档案的 WebView 回落到与普通
模式共用一份存储，模式首页的说明按实际能力显示，不提前宣称隔离。隔离粒度是
「指纹模式整体一份」，不是每个档案组合一份——模式同一时间只呈现一个身份，
粒度与产品形态一致；逐组合分开是可继续的方向，不在本表承诺内。

注 2（代理）：androidx.webkit 的 ProxyController 是全 App 级覆盖（对所有 WebView 生效、
Gecko 不受影响），没有逐档案粒度。可落地的形态是「指纹模式级」绑定：进入指纹模式时
应用、退出时清除，并用现有 IP 自查验出口。逐档案独立代理在 WebView 路线内做不到，
除非每个档案配一个独立进程——那是另一量级的改造，不在本表承诺内。

本表随版本更新；每项状态变化时同步改表并在检查点记明依据。
